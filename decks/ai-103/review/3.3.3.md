# 3.3.3 Transcribe speech

Course quality: thin — it names three transcription models without saying how they differ (diarize is never explained) and shows one code sample with little commentary.
Cards: 2 (basic 1, mc 1, order 0). Additions: 2.
- 3.3.3-01: the course never says what "diarize" means. Diarization = identifying who spoke when, giving speaker-attributed transcripts. Source: https://learn.microsoft.com/en-us/azure/foundry-classic/openai/whats-new (October 2025 entry).
- 3.3.3-02: the course gives no size limit. Speech-to-text models on the `/audio` API take at most a 25 MB audio file per request; streaming transcription goes to Realtime API models (`gpt-realtime-whisper`, `gpt-live-transcribe`). Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure?pivots=azure-openai (Audio API, speech-to-text table).
- The current models page also lists `whisper` and `gpt-transcribe` as speech-to-text models; the cards keep to the course's three names.
- No "which model transcribes?" mc: the module assessment (3.3.7) asks exactly that (gpt-4o-mini-transcribe vs. -tts), so it is not duplicated here.
- No images: the unit has none.
