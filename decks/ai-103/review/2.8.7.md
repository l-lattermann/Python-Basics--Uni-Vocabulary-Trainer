# 2.8.7 Use handoff orchestration

Course quality: thin — use and avoid criteria are clear, but the implementation is a bullet list without code, and it describes a hand-built switch-case control workflow while the SDK ships a dedicated handoff builder.
Cards: 4 (basic 3, mc 1, order 0). Additions: 1.

Terms:
- Handoff orchestration (2.8.7-01)
- When to avoid handoff orchestration (list card 2.8.7-02): fixed agents and order, simple rule-based routing, poor routing frustrates users, parallel operations, infinite handoff loops (2.8.7-02)
- Specialized executors (list card 2.8.7-03): Input storage executor, Transformation executor, Handler executors (2.8.7-03)
- Routing logic: switch-case edge group, Case objects, Default case, `WorkflowBuilder` (2.8.7-04)

- 2.8.7-04 addition: the course builds handoff by hand from executors and switch-case edges; current Agent Framework docs offer `HandoffBuilder`, a mesh of agents without orchestrator that hand off via auto-registered handoff tools. Source: https://learn.microsoft.com/en-us/agent-framework/user-guide/workflows/orchestrations/handoff (redirects to /agent-framework/workflows/orchestrations/handoff).

- The four implementation steps get no order card (budget). The step contents are spread over the explanations of 2.8.7-03 and 2.8.7-04.
