# 2.8.6 Use group chat orchestration

Course quality: confusing — the concept and the manager's call order are clear, but the implementation steps are copied from concurrent orchestration and claim the group chat runs agents in parallel.
Cards: 5 (basic 3, mc 2, order 0). Additions: 2.

Terms:
- Group chat orchestration (2.8.6-01), chat manager (2.8.6-01)
- When to avoid (2.8.6-02; the two correct options, the other three in the explanation)
- Maker-checker loop: maker, checker (2.8.6-03)
- Group chat manager call order (list card 2.8.6-04): `should_request_user_input`, `should_terminate`, `filter_results`, `select_next_agent` (2.8.6-04)
- `GroupChatManager` base class (2.8.6-04, explanation; the four overridable methods are in the answer)
- `GroupChatBuilder`, `participants()`, `build()` (2.8.6-05)

- 2.8.6-04 addition: the current Agent Framework Python docs configure speaker selection with `GroupChatBuilder(selection_func=…, orchestrator_agent=…, orchestrator=…, termination_condition=…)`, not by overriding the four manager methods. Source: https://learn.microsoft.com/en-us/agent-framework/user-guide/workflows/orchestrations/group-chat
- 2.8.6-05 addition: the course's steps 3–4 say the group chat "runs all agents concurrently" (copied from 2.8.4). The docs say the orchestrator picks one speaker per turn and broadcasts each response. Same source.
- The remaining implementation steps (`AzureOpenAIChatClient`, `create_agent`, `run`, `get_outputs()`) are word for word those of 2.8.4. They appear only in the explanation of 2.8.6-05, so the cards do not duplicate the neighbour.
- The "when to use" list and the common scenarios are not defined terms. They sit in the explanation of 2.8.6-01 and as wrong options in 2.8.6-02.
