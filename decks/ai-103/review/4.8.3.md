# 4.8.3 Extract data with an indexer

Course quality: clear — the growing JSON tree makes the enrichment pipeline easy to follow; it names no settings (`imageAction`, `fieldMappings`, `outputFieldMappings`, context paths), which the additions supply.
Cards: 10 (basic 7, mc 2, order 1). Additions: 4.
- 4.8.3-05: the course says "configure the indexer to extract the image data" without naming the setting; `imageAction` = `generateNormalizedImages` / `generateNormalizedImagePerPage`, extra charge — https://learn.microsoft.com/en-us/azure/search/cognitive-search-concept-image-scenarios
- 4.8.3-06: context path syntax `/document/normalized_images/*` — same source.
- 4.8.3-09: explicit source mappings live in `fieldMappings`, with mapping functions such as `base64Encode` — https://learn.microsoft.com/en-us/azure/search/search-indexer-field-mappings
- 4.8.3-10: skill outputs go in `outputFieldMappings` and exist only in memory until mapped — https://learn.microsoft.com/en-us/azure/search/cognitive-search-output-field-mapping
- Image: `4.8.3-indexer.png` (data source → indexer → index) on 4.8.3-01; the other diagrams of this unit are only the bulleted trees, which the cards render as text.
- Neighbour overlap avoided: built-in vs custom skills belong to 4.8.4, index field attributes and querying to 4.8.5, projections to 4.8.6; the module assessment's "which component is scheduled to extract and enrich" stays with 4.8.10. Card 4.8.3-01 covers the three components as the unit's core definition.
- The course uses "merge skill"; the docs call it Text Merge (`Microsoft.Skills.Text.MergeSkill`). Not added as an addition: the name difference is minor and the card's answer holds either way.
