# 4.8.6 Persist extracted information in a knowledge store

Course quality: thin — it names the knowledge store, its three projection kinds and their use cases, but never says that the store lives in Azure Storage or which storage service holds which projection.
Cards: 3 (basic 2, mc 1, order 0). Additions: 3.

Terms:

- Projections — 4.8.6-01
- Object projections (JSON objects) — 4.8.6-02
- Table projections (tables) — 4.8.6-02

- 4.8.6-01: the course never says where a knowledge store physically lives; added Azure Table/Blob Storage, consumption by any Storage-capable tool, and no query support in AI Search (https://learn.microsoft.com/en-us/azure/search/knowledge-store-concept-intro).
- 4.8.6-02: added which storage service each projection kind goes to; file projections land in Blob Storage, not Azure Files (same source).
- 4.8.6-03: added the `knowledgeStore` element's structure (connection string + projections array) and that projections survive deleting the indexer or skillset (same source).
- The course says "JSON objects, tables, or image files"; the card names them Object/Table/File projections as the module assessment (4.8.10, Q3) and the docs do. That assessment asks which projection gives a relational schema, so no separate scenario card for table projections was written here.
